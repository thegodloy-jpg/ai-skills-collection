# Markdown 的阅读、修改与检查

## 文本格式

- 使用真实标题层级表达包含关系；标题编号和层级对应，保留用户要求的模板章节。文档已有有效的编号体系时沿用，不机械改成固定章数。
- 一份正文通常只有一个文档级标题。长文可使用可导航的小标题；“伪代码”“代码位置”“代码说明”等短模块标签可用加粗，避免每个标签都新增目录层级。
- 一段表达一个主要意思。顺序步骤使用有序列表，并列事项使用无序列表；表格用于映射或比较，连续论述使用段落。是否删表服从当前任务。
- 代码使用带语言的围栏，伪代码通常使用 `text`。保留代码缩进、原有换行和必要注释。精简代码示例需要用户授权，并清楚标注省略；不为排版改写代码逻辑。
- 图片使用可迁移的相对路径，图注紧随图片；引用方式和图编号保持一致。不要凭同名文件判断 PNG 与 SVG 是同一版本。
- 通过 Markdown 的语义结构组织内容。字体字号、固定行距和页面方向在 Word 中实现；不靠大量空行、全角空格或强制换行模拟纸面版式。
- 本地资源链接按 MD 所在目录解析。完整资料包需要一起携带图片目录；项目源码定位可保留为代码路径，是否转成可点击链接取决于交付范围。

## 逻辑格式

先判断本轮处理哪一层，再调整相应内容：

| 层面 | 检查问题 |
| --- | --- |
| 章与章 | 每章承担什么职责？是否重复？后文是否承接前文？ |
| 总览与子模块 | 总览是否覆盖完整链路？子模块是否展开总览中的同一个对象？ |
| 同级子章节 | 粒度是否相近？是否围绕同一类问题展开？ |
| 模块内部 | 先说明什么、再解释什么？图、伪代码、源码和说明是否对应？ |

采用用户指定模板时，模板的强制章节保留；内容不涉及时按用户或模板要求归拢。通用规则不强制所有技术文档采用同一种章节结构。

伪代码表达功能动作、必要条件及失败边界，保留有助于对应源码的关键变量。主流程覆盖完整执行链路；子模块展开本模块的核心机制。依据源码决定是否存在回滚、重试、降级或异步释放，不能把通用伪代码框架套成实际实现。

真实代码挑选支撑伪代码的关键函数，可跨目录联动展示。示例保持真实函数归属和必要分支；省略非核心参数或语句后仍要能读懂。功能准确性优先于压缩篇幅。

## 多轮交互

1. 把本轮反馈映射到具体章节、段落、图或代码块，再修改相应位置。
2. 合并、拆分或移动章节后，联动维护编号、图注和“见某节”等引用。
3. 局部修改服从用户范围；只有影响上下文一致性时才调整相关位置。
4. 已确认约定在后续轮次持续有效；新要求覆盖冲突的旧要求。不要在相邻轮次反复切换已确定的展示方式。
5. 检查意见与正文分离。交互中可在回复里列出问题；用户确实需要长期留存时，再生成独立审阅清单。

## 自动检查器

运行环境：Python 3，`markdown-it-py`。使用当前已有环境；缺少依赖时报告具体缺项，按任务需要补齐环境。

```text
python <skill-dir>/scripts/check_markdown.py <工作稿.md>
python <skill-dir>/scripts/check_markdown.py <定稿.md> --final --report <检查结果.json>
```

检查器只读输入，报告包括标题、代码块、图片、表格计数和带行号的问题。返回码：`0` 无错误，`1` 发现错误，`2` 运行失败。警告用于人工复核，不等于文档有确定缺陷。

- 结构检查：标题跳级、多文档级标题、可识别的同级重复编号、未闭合代码围栏。
- 资源检查：本地图片缺失作为错误；普通本地链接缺失默认警告，`--strict-links` 时作为错误。网络地址只识别类型，不发请求。
- 定稿检查：`--final` 提醒明确的审阅标记和待补内容。它不能代替通读，也不能判断伪代码与真实代码是否等价。

提交修改前，按范围重读正文，并对照代码和图片资源。避免为了让检查器没有警告而删除合理内容或改动技术含义。
