# Word 的格式、转换和验收

## 模板及参数的优先级

采用用户明确要求的样式；其后依次使用指定 Word 模板、选定项目规范、通用默认值。模板中的正文和旧图片不属于新文档内容。保留有用的标题样式、页眉页脚和编号设计，检查旧分节是否会意外改变新文档方向。

没有参考模板时，可使用下列技术文档默认值。这些是初始值，不能覆盖用户的明确要求。

| 对象 | 默认排版 |
| --- | --- |
| 纸张 | A4 纵向，四边 72 pt（2.54 cm）页边距 |
| 文档标题 | 宋体 18 pt、加粗、居中 |
| 一级／二级／三级标题 | 宋体 16／15／13 pt，体现清晰层级 |
| 正文 | 宋体 12 pt，首行 24 pt，1.2 倍行距 |
| 代码与伪代码 | 拉丁字符 Consolas、中文宋体，9.5 pt，固定行距 11.5 pt，保留缩进 |
| 图注 | 宋体 10.5 pt、加粗、居中，与图片同页 |
| 数据表 | 宋体 10.5–11 pt，重复表头，单行保持完整 |

代码块沿用 `MD Code` 段落样式的实际字体；模板没有该样式但有 `Wings Code` 时继承后者。`--style-json` 中的明确字体配置优先，例如 `{"MD Code": {"font": "Courier New", "east_asia": "仿宋"}}`。行内代码也采用 `MD Code` 的字体，字号仍沿用所在段落；没有模板或覆盖配置时，代码默认使用 Consolas 与宋体。

## 分页与空间

- 标题与首段关联；图片只与图注关联，避免无意中把后面一整节拖到下一页。
- 长代码允许在合理位置分页。逐行保持完整，声明、条件及紧随其后的第一步避免孤立；不要求整个长代码块同页。
- 代码超出可用宽度时，先检查布局、缩进及已批准的示例取舍。确需修改源代码换行或精简内容时回到 MD 阶段；不静默缩小字号或丢弃代码。
- 图片等比例放置并限制在正文范围。读取真实图源，不裁切文字，不把历史同名 PNG 当成当前 SVG 的等价图。
- 数据表按内容分配列宽和内边距，优先保持可读字号。宽表是否使用横向节取决于用户要求；双版本和 ZIP 均按需交付。
- 横向 A4 为 297×210 mm，纵向 A4 为 210×297 mm。比较纸型与正文可用区域时，同时检查纸张宽高和页边距。纸张方向与内容旋转是不同要求。
- 减少不必要的分页符和整体“与下段同页”链。章节结束或横向节之前的自然留白需结合阅读逻辑判断，不承诺每一页都填满。

## 配套转换器

依赖：Python 3、`python-docx`、`markdown-it-py`、`lxml`、`Pillow`。它适用于常见技术 Markdown，以 A4 正文转换为边界；指定其他纸型、复杂编号或特殊分节时，使用能保留这些要求的转换方式。

```text
python <skill-dir>/scripts/build_word.py <定稿.md> --output <输出.docx>
python <skill-dir>/scripts/build_word.py <定稿.md> --output <输出.docx> --template <参考.docx> --report <转换核验.json>
```

精确选项以 `--help` 为准。脚本支持常见标题、段落、列表、行内强调与代码、链接、图片、代码块及表格。对不支持的结构须明确失败或说明待处理，不能跳过内容后声称保真。

SVG 等图源先使用可用渲染器转换，并检查图像内容；通过 `--image-map` 显式指定映射。映射文件为 JSON 对象，例如 `{"assets/arch.svg": "rendered/arch.png"}`；键为 MD 中的原始图片路径或源图绝对路径，值为渲染后的 PNG/JPEG 路径，相对值按映射文件目录解析。不要靠同名 PNG 自动替换。Mermaid 等图示先渲染并在选定工作稿中建立明确资源引用，或选择能够正确处理该结构的转换工具。

转换器保留普通网页、邮件及文内标题链接。本地文件超链接、未渲染图示和不支持的 HTML 会明确报错；表格中常见的 `<br>`、`<br />` 换行可以处理。遇到这些限制时，采用能保留结构的其他转换方式，或在授权范围内整理 MD，不能静默删掉链接或标签内容。

独立图片优先使用紧随其后的显式图注段落：下一段的完整显示文字与图片 alt 完全相同，或以 `图N`／`Figure N` 数字标记开头时，将该段按 `Caption` 样式输出一次，保留其文字和行内格式，不再另加 alt 图注。只检查紧邻的下一个段落，不跨标题、列表或其他内容搜索。没有匹配的显式图注时，仍以非空 alt 生成图注；alt 为空且没有显式图注时不生成。图片的 alt 元数据始终保留原值，后续普通正文保持原序。

需要横向末节时，明确传入 `--landscape-heading`，用真实标题文本定位开始位置。没有该要求时生成纵向文档。输出存在时默认保留，显式使用 `--overwrite` 才替换指定输出；源 MD 和参考模板始终保持原样。

脚本在临时输出上比较正文、代码和表格内容及图片计数，再发布目标文件。生成报告中的结构检查不代表已检查实际页面；报告应标明 `visual_validation=not_run`，直到实际渲染后另行记录。

## 域与外部关系

- 检查 `updateFields`。普通静态讲解稿可关闭打开时自动更新全部域，保留正常的 `PAGE`、`NUMPAGES`。用户需要动态目录等功能时按需求处理，不能一律关闭所有更新或删除全部域。
- 外部普通网页超链接与外部文件、模板、DDE、嵌入对象引用分别检查。不能看到 `TargetMode=External` 就认定是危险或错误，也不能声称不存在实际未检查的外链。
- 页码总数不能写死为历史的 24 页。重新分页后核对页码与页数；已有缓存可能过期，关闭自动更新本身不能证明显示正确。
- 对“是否更新引用其他文件的域”的提示，同时检查设置、域指令及关系。修复后实际打开验证；表述为当时环境的观察结果。

## 实际验收

1. **内容一致性**：按内容块比对正文次序、代码行、表格单元格及图片资源。转换造成的 Word XML 排列或元数据差异不视为正文变化。
2. **结构检查**：DOCX 有效，字体配置、图片嵌入、节尺寸、表头、域及关系符合要求。
3. **渲染检查**：使用可用的 Word 实例导出 PDF，检查代表性页面及代码、图表密集页，发现问题再扩大检查范围。确认代码折行、裁切、字体替换、大块异常留白和页码。
4. **保护会话**：Windows 自动化创建独立隐藏的 Word 实例，只关闭自己创建的文档与进程，保留用户现有 Word 会话；若调用辅助后台进程，保持隐藏窗口。
5. **结论边界**：记录实际执行的检查。未进行真实打开或 PDF 渲染时明确说明，不把静态设置检查写成“已无弹窗”或“分页正常”。

Word 阶段发现正文问题后，按用户范围更新 MD 并重新生成。需要 ZIP 时，附相对路径图片资源、必要说明和校验信息，并实际解压验证。
