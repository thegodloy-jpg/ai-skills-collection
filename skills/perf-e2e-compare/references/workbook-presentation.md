# 表内展示契约

用于在已有的性能工作簿中呈现已核实的运行配置和场景 SLA。此步骤不计算新指标，不把单次实验认定为基线，也不替代基线/调优对比。

## 输入与作用范围

使用 UTF-8 JSON，`sheets` 数组中的 `sheet` 必须与工作簿的表名完全一致。每项可选择填写 `hardware_text`（D 列）、`software_text`（E 列）、`parallelism_text`（F 列）以及 `scenarios`。后者用 `name` 与 G 列中现有场景名称精确匹配；可显式给出 `display_name`、`sla_text`、`feature_text`，分别作用于 G、H、I 列。文本覆盖对应单元格；未提供的字段不改动。比较工作簿不允许改 G 列名称，避免破坏场景匹配。长命令显示不全时，可显式配置 `software_column_width` 和 `data_row_height` 以调整 E 列宽与数据行高；缺省不改变原布局。脚本只处理使用区域不超过 1000 行、26 列的标准性能工作簿；超出或无法确定合并场景块时停止。

```json
{
  "sheets": [
    {
      "sheet": "实测",
      "software_text": "OS:<已核验系统>\n推理引擎:<已核验镜像>\n测试执行命令:\n<原始启动命令>",
      "parallelism_text": "<已核验的并行配置>",
      "software_column_width": 80,
      "data_row_height": 28,
      "scenarios": [
        {
          "name": "<工作簿中已有的场景名>",
          "sla_text": "TPOT≤70ms\nTTFT≤9秒",
          "feature_text": "<实际使用或用户指定的加速特性>",
          "tpot_limit_ms": 70,
          "ttft_limit_s": 9,
          "eligible_concurrency": [1, 2]
        }
      ]
    }
  ]
}
```

以上数字仅示意字段结构，不是可直接使用的数据。启动命令保持已核实原文的换行、引号及变量，不能混合不同运行或包含密码、token、私钥。明确每个 sheet 对应的运行与证据状态；发现命令、软件版本或运行角色不明时不猜测。加速特性按实际运行或用户的明确映射填写，不自动将 DSpark 映射成已验收的产品功能。避免重复写入已有的并行配置或“历史补充”段落。

## 软件版本与启动命令

当用户要求在 E 列补充软件环境或提供了“版本信息在前、启动命令在后”的示例时，在 `software_text` 中先逐行列出有证据的环境信息，再保留对应运行的环境变量和完整启动命令；不要让示例中其他硬件或模型的值进入本次工作簿。按场景适用性选取硬件与并行、宿主及容器系统、驱动、CUDA 或 CANN、Docker、Python、PyTorch、torch-npu、Transformers、vLLM、vLLM-Ascend、镜像名称与 ID 等字段；没有可信来源的字段留空或省略，不由其他组件版本推断。版本字符串按原证据完整保留，包括构建后缀。

为每项区分镜像内软件、实测时宿主状态和事后宿主快照；快照不能冒充历史实测版本，必要时标注采集日期。镜像 ID 应与被汇总的运行相匹配；如容器由 Docker 注入环境变量，在命令前单独标注其来源，避免把该变量误写为服务脚本原文。PyTorch 的包后缀如 `+cpu` 只按包版本原样记录，不单凭后缀推断实际设备；Ascend 场景可分别写 PyTorch 和已核实的 torch-npu 版本。

只补版本时，先读取目标 E 列并保留原来准确的命令和其他已核实信息；未提供的其他列和场景保持不变。若现有文本与证据冲突，保留来源并明确差异，不能静默拼成同一次运行。附来源文件或可核验的记录，验证更新后的 E 列及原性能数据，避免把模板字段或新增版本当作该次测量已验证的配置。

`sla_text` 是显示文字。仅当同时提供正数 `tpot_limit_ms`、`ttft_limit_s` 和 `eligible_concurrency` 数组时，才重算绿色高亮。调用方必须依据原始数据核查每个并发点的成功/失败、完成情况和证据状态，明确列出有资格参与判定的并发；表里缺失失败信息时不能默认零失败。脚本仅在这些合格点中，按平均 TPOT（O 列，ms）与平均 TTFT（M 列，秒）选出同时满足两个上限的最高并发；没有合格或达标点则不标绿。重算前必须核实场景、并发和时延表头及单位，不能把毫秒误当作秒。数值不等于显示文字的近似区间下限；不要从示例猜测上下限。只修改展示文字而不提交上限时，须由调用方核实 SLA 判定规则未变，并显式提供 `sla_limits_unchanged: true`；脚本保留既有高亮，不能代替这一核实。如 SLA 上限已变化，必须提供成对上限及合格点并重算。1M 场景同样只用明确提供的门限，未提供时不编造。

高亮只调整明确识别的 J:T 数据区域；若该场景块的 U:X 存在相同绿色，无法安全判断其是旧 SLA 标记还是业务颜色时停止，避免留下孤立标记或覆盖用户的比较列格式。仅更新展示文字且不重算高亮时，保留这些颜色。

前缀数据如果只是配置比例，应写“前缀比例”，不能写成实测缓存命中率。总 E2E 吞吐保留原始 `total_token_throughput`，不得根据展示的正文 token 长度重算；Q/S 按并发拆分时是总吞吐的平均值，并非逐请求实测。

## 验证与保存

输入工作簿必须未打开、未锁定，输出必须是不存在的新路径。通过 Excel COM 在独立实例中处理，完成后只清理本步骤创建的实例；不得关闭或覆盖已有用户会话。回读核验单元格值、公式、数字格式、字体、对齐、填充、合并与有效边框，以及 E/H/I/F 的写入和明确阈值的高亮。应保留 E2E 与对比列原值；格式化步骤自身不等同于 E2E 比较流程验收。脚本并未完整检查图形、数据验证、条件格式或工作簿计算设置；涉及这些对象时须额外核验，不能笼统宣称整本工作簿的所有对象均未变化。若发生冲突、无法读取目标场景或验证失败，保留输入，停止发布。

成功时脚本输出 `PRESENTATION_VALIDATION=PASS`、输出文件路径与 SHA-256。保留 JSON、脚本输出和源数据引用，明确无独立对照的表不能生成提升比。
